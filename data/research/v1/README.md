# Adaptive Research Seed Catalog v1

This directory contains the public design-data seed for **Stellar Continuum's Adaptive Research System**.

## What this is

This is **not** a fixed player-visible technology tree. It is a universe-scale **Technology Possibility Graph** from which each civilization materializes a much smaller changing research horizon.

The current public seed contains:

- **330 normal/public possibility nodes across 20 domains**
- **59 Research Pressure types** with ordinary generation/decay rules
- **6 public applicability traits**
- **9 public evidence types**
- **15 alternative-solution sets**

Exact hidden discoveries, rare secret technologies/evidence, secret AI eligibility, and artifact chains are intentionally excluded.

## Core files

- `index.json` — catalog metadata, pressure definitions, domain list/counts, alternative-solution sets, and domain file map.
- `research_economy.json` — Research Point, Research Pressure, Research Lab, concurrency, lab-scaling, and seeded node requirement rules.
- `research_capacity.json` — effective lab capacity and staged directed-program coordination.
- `emergence_model.json` — bounded event/index-driven candidate-emergence pipeline.
- `applicability_traits.json` — stable biology/civilization capability traits used by nodes; never race IDs.
- `evidence_types.json` — stable ordinary evidence types and campaign evidence-instance model.
- `pressure_dynamics.json` — generation/decay inputs for all 59 Research Pressure types.
- one JSON file per research domain — possibility nodes.

Human-readable architecture:

- `docs/ADAPTIVE_RESEARCH_SYSTEM.md`
- `docs/RESEARCH_ECONOMY.md`
- `docs/RESEARCH_CAPACITY_MODEL.md`
- `docs/RESEARCH_EMERGENCE_MODEL.md`

## Runtime rule

Do **not** copy all 330 possibilities into every civilization save or keep them active for every civilization.

A civilization persists only compact state such as:

- known/mature node IDs
- visible hypotheses/candidates
- active directed projects and RP progress
- effective Research Lab capacity and assignments
- sparse Research Pressure values relevant to known fields
- evidence instances
- mutable civilization applicability traits
- population/species applicability contexts
- field competencies/priorities

The static catalog is indexed once. Candidate nodes are reconsidered only when relevant state changes: pressure bands, evidence, prerequisites, trait changes, or bounded basic-science review.

## Node fields

Common node fields include:

- `id` — stable save-safe identifier
- `name` — player-facing working name
- `domain`
- `complexity` — foundation/developing/advanced/frontier
- `graph_depth` — approximate depth for seed cost/scaling
- `solution_family` — groups technological traditions
- `knowledge_fields`
- `awareness_sources`
- `pressure_affinities` — pressures that make the idea contextually relevant; **these do not automatically create a hard availability gate**
- `prerequisites.all_of` / `prerequisites.any_of`
- `applicability.requires_traits`
- `applicability.requires_evidence`
- `capabilities`
- `is_hypothesis`

## RP + Pressure + Labs

Every directed project consumes scientific work measured in **Research Points (RP)** generated by Effective Research Labs.

Every project also requires a minimum assigned-lab capacity. More labs can accelerate work with diminishing returns.

**Research Pressure is separate from RP.** Only technologies explicitly configured with `required_pressure` or `required_pressure_any` are hard-gated by pressure. Complexity alone never creates a pressure requirement.

Early civilizations direct one major strategic program. Research-infrastructure discoveries later unlock 2, then 4, then lab-capacity-limited simultaneous directed programs. Unassigned laboratories continue diffuse/basic science.

## Emergence and pressure performance

Pressure is sparse state derived from owning simulation subsystems rather than from tech-tree scanning.

Examples:

- economy reports normalized food/resource/energy conditions
- combat reports actual observed weapon/armor/mobility outcomes
- health reports gravity/radiation/disease burdens
- exploration reports anomalies/alien observations
- logistics reports supply-line and transport stress

The research layer updates only affected pressures. Static indexes then wake only nodes connected to a changed pressure/evidence/prerequisite/trait.

AI and player civilizations use the same rules. Relative enemy pressures require legitimate observations; authoritative hidden enemy stats do not create pressure.

## Applicability traits

Traits describe **what is biologically or technologically possible**, not which named species is being played.

Population/species traits apply to the relevant population. Civilization traits can be acquired through technological history. For example, biological fabrication capability or machine cognition can emerge later and expose research branches that were previously inapplicable.

## Evidence

Campaigns store evidence instances referencing static evidence type IDs. Evidence can have provenance, quality, confidence, intactness, custody, and age/state.

Evidence can expose or support research but never instantly grants a technology.

## Validation

Run:

```text
python3 scripts/validate_research_catalog.py data/research/v1
```

CI runs the same validator before the .NET/Godot gates.

The validator checks:

- declared domain/node counts
- duplicate node/domain/pressure/trait/evidence IDs
- missing prerequisites
- unknown pressure references
- complete pressure-dynamics coverage
- unknown applicability traits/evidence types
- alternative-solution references
- research-economy override references
- research-capacity technology references
- lab/RP requirement validity
- prerequisite cycles
- public-catalog secrecy flags

## Balance status

The current catalog is architectural seed data, not final commercial balance. RP costs, pressure thresholds, lab output, pressure approach/pulse values, evidence thresholds, and efficiency curves should be tuned through long-run simulation while preserving the adaptive graph and **RP + Pressure + Labs** model.
